# Mirage 产品设计文档

> 文档版本：V1.0  
> 产品阶段：MVP / 原型验证  
> 产品主张：**让现实，多一层想象。**

---

## 1. 产品概述

### 1.1 产品名称

- 中文名：幻镜
- 英文名：Mirage
- 产品类型：iOS 实时特效相机
- 核心技术：UIKit、AVFoundation、ARKit、RealityKit

### 1.2 产品定位

Mirage 是一款融合自拍、相机滤镜和空间 AR 的实时特效相机。用户不需要了解 3D、空间追踪或面部识别技术，只需选择一个特效，将镜头对准自己或周围空间，即可完成具有沉浸感的照片和视频创作。

产品不会只定位为“AR 工具”，而是定位为“可持续增加玩法的创意相机”。这样未来可以自然扩展自拍、美颜、滤镜、空间特效、人物特效、视频模板和 AI 创作能力。

### 1.3 核心价值

1. **简单**：打开即可拍摄，不要求用户学习 AR 操作。
2. **有趣**：特效必须在几秒内产生明显、可分享的视觉反馈。
3. **真实融合**：特效能理解面部、人体或空间，而不只是覆盖一张贴图。
4. **持续扩展**：新增特效不需要重写相机核心流程。

### 1.4 一句话介绍

> 一款能把想象放进自拍和现实空间的 iOS 特效相机。

## 2. 目标用户与使用场景

### 2.1 核心用户

- 喜欢自拍、美颜和新奇视觉效果的年轻用户。
- 喜欢在社交平台发布照片或短视频的内容创作者。
- 对 AR 新玩法感兴趣，但不熟悉专业创作软件的普通用户。
- 希望快速验证 RealityKit、ARKit 创意的设计师和开发者。

### 2.2 典型场景

#### 场景 A：自拍特效

用户切换到前置镜头，选择面具、头饰、妆容、光环或粒子特效，完成自拍并保存或分享。

#### 场景 B：空间特效

用户使用后置镜头扫描桌面、地面或房间，把晶体、传送门、角色或粒子场放入真实空间。

#### 场景 C：互动特效

特效根据眨眼、张嘴、手势、身体动作、屏幕点击或设备移动触发变化。

#### 场景 D：主题内容创作

用户从特效库选择节日、动漫、电影感或自然主题，录制一段短视频并分享。

## 3. 产品原则

### 3.1 相机优先

打开 App 后直接进入相机，不用先经过首页、广告或内容流。拍摄是整个产品的主任务。

### 3.2 技术隐形

界面不展示“World Tracking”“Face Anchor”等技术术语，统一转化为用户能理解的“自拍”“空间”“寻找平面”等表达。

### 3.3 三秒可理解

每个特效应在选中后三秒内告诉用户：它是什么、应该对准哪里、如何触发。

### 3.4 能力自动适配

App 自动检查 TrueDepth、LiDAR、人体追踪等能力。不支持时隐藏对应特效或给出替代方案，不让用户面对系统错误。

### 3.5 特效资源化

核心程序提供稳定的相机、追踪、渲染和交互能力；特效尽量由资源和配置组成，便于后续下载、更新和运营。

## 6. 核心用户流程

### 6.1 首次启动

```text
启动 App
   ↓
展示相机权限说明
   ↓
用户授权相机 ─── 拒绝 ──→ 权限说明页 → 前往系统设置
   ↓
进入空间相机
   ↓
选择特效 → 按照引导移动设备 → 特效出现
   ↓
拍照 → 预览/系统分享
```

### 6.2 自拍流程

```text
空间相机 → 点击镜头切换 → 检测面部追踪能力
                                  ↓
                        支持：进入自拍模式
                        不支持：提示并回到空间模式
                                  ↓
                        选择自拍特效 → 拍摄
```

### 6.3 空间特效流程

```text
选择空间特效
   ↓
提示“移动手机寻找平面”
   ↓
识别到平面
   ↓
显示放置提示
   ↓
点击放置 → 可移动/缩放/旋转 → 拍摄
```

## 7. 页面设计说明

### 7.1 相机主页

相机主页采用全屏沉浸式布局，所有控件浮在相机画面上。

#### 顶部区域

- 左侧：`MIRAGE` 品牌字标。
- 品牌右侧：当前模式标签，如“空间 AR”或“自拍”。
- 右侧：切换前后镜头按钮。
- 后续可增加闪光灯、比例和设置入口，但首版避免顶部过于拥挤。

#### 中央区域

- 主要显示相机与实时特效。
- 操作提示使用半透明黑色胶囊，例如“移动手机，探索周围空间”。
- 提示在完成条件后自动淡出，避免持续遮挡画面。

#### 特效区域

- 位于快门上方，使用半透明毛玻璃面板。
- 每个特效包含图标和名称。
- 选中状态使用白色背景与深色文字。
- 自拍和空间模式只展示当前可用的特效。
- 特效较多时改为横向滚动，不压缩每个选项。

#### 拍摄区域

- 中央为大尺寸白色快门按钮。
- 左侧为作品入口。
- 右侧预留拍照/视频模式或镜头参数入口。
- 点击快门有缩放和触觉反馈。

### 7.2 权限说明状态

- 背景保留暗色相机界面，中央显示毛玻璃卡片。
- 标题：“需要相机权限”。
- 说明：“Mirage 使用相机呈现并拍摄实时 AR 特效。”
- 主操作：“前往设置”。
- 不使用容易引发担忧的技术描述，不暗示会上传相机内容。

### 7.3 特效库（下一阶段）

- 顶部：标题、搜索、已下载入口。
- 分类：精选、自拍、空间、互动、节日。
- 卡片：预览图、名称、资源大小、下载状态。
- 点击卡片进入预览详情，点击“使用”返回相机并自动选中。

### 7.4 作品页（下一阶段）

- 使用照片网格展示本地创作。
- 支持照片、视频和草稿筛选。
- 长按进入多选管理。
- 默认只读取 Mirage 自己创建的内容，访问系统照片库时再单独申请权限。

## 8. 视觉设计规范

### 8.1 品牌气质

关键词：**梦幻、空间感、轻盈、未来、克制**。

视觉不采用复杂的科技线框和高饱和赛博朋克风格，而是让相机内容成为主角，通过深色背景、轻量渐变和毛玻璃建立品牌识别。

### 8.2 色彩

| 用途 | 色值 | 说明 |
|---|---|---|
| 深色背景 | `#07070C` | 无相机画面时的基础背景 |
| 主文字 | `#FFFFFF` | 标题和主要操作 |
| 次级文字 | `rgba(255,255,255,0.72)` | 提示和辅助信息 |
| 品牌紫 | `#A879FF` | 选中、光效、重点状态 |
| 星光蓝 | `#63D8FF` | 空间与粒子特效辅助色 |
| 梦境粉 | `#FF6EBD` | 自拍和情绪化特效辅助色 |
| 遮罩 | `rgba(0,0,0,0.35)` | 提升相机画面上的文字可读性 |

### 8.3 字体

- 使用系统字体 SF Pro，中文自动使用苹方。
- 品牌字标：18pt / Black / 大写。
- 页面标题：24pt / Bold。
- 模块标题：13–15pt / Semibold。
- 正文：14–16pt / Regular。
- 提示文字：13pt / Medium。
- 特效名称：11–12pt / Semibold。

### 8.4 圆角与间距

- 页面横向安全边距：16pt。
- 普通控件间距：8pt 或 12pt。
- 模块间距：16pt 或 24pt。
- 图标按钮：44 × 44pt，圆角 22pt。
- 特效面板圆角：24pt。
- 提示胶囊圆角：16–18pt。
- 快门按钮：76 × 76pt。

### 8.5 材质

- 浮层采用 iOS 原生毛玻璃材质。
- 深色场景使用 `systemUltraThinMaterialDark`。
- 控件需保证在亮色和暗色相机背景下都有足够对比度。
- 不用大面积不透明面板遮挡取景画面。

### 8.6 动效

- 页面控件出现：淡入 180–240ms。
- 特效切换：选中项缩放至 1.05，再回到 1.0。
- 快门：按下缩放至 0.86，释放恢复。
- 特效加载：使用轻量粒子或渐变圆环，不使用普通系统菊花占据画面中央。
- 错误提示：居中 Toast，约 1.6 秒后淡出。

## 9. 特效产品模型

### 9.1 特效分类

| 类型 | 依赖能力 | 示例 |
|---|---|---|
| 自拍特效 | 面部追踪 | 眼镜、头饰、光环、面具、妆容 |
| 空间特效 | 世界追踪、平面检测 | 晶体、传送门、角色、空间粒子 |
| 人体特效 | 人体追踪 | 服装、骨骼光效、动作残影 |
| 手势特效 | 手部识别或视觉模型 | 手心火焰、手势召唤、粒子控制 |
| 图像特效 | 图像锚点 | 海报复活、卡片动画、包装互动 |
| 环境特效 | 深度、场景重建 | 遮挡、墙体变化、空间重构 |

### 9.2 特效包建议结构

```text
EffectPackage/
├── manifest.json
├── thumbnail.webp
├── preview.mp4
├── scene.usdz
├── textures/
├── audio/
└── configuration.json
```

`manifest.json` 至少包含：

- 特效 ID 和版本。
- 名称、分类和缩略图。
- 最低系统版本。
- 需要的设备能力。
- 入口锚点类型。
- 资源哈希和下载大小。

### 9.3 原生扩展接口

每个原生特效遵循统一的 `MirageEffect` 协议，声明：

- 唯一标识。
- 展示名称与图标。
- 支持的相机模式。
- 安装 RealityKit 实体的逻辑。
- 移除与释放资源的逻辑。

远程扩展应下载资源和配置，由 App 中已经审核的原生能力解释执行，不下载并运行 Swift 代码。

## 11. 权限与隐私

### 11.1 权限申请时机

- 相机：首次进入相机时申请。
- 麦克风：第一次录制视频时申请，不在首次启动时一起申请。
- 照片库：用户主动导入或保存到系统照片时申请。
- 不申请与产品功能无关的定位、通讯录或蓝牙权限。

### 11.2 隐私原则

- 相机画面默认在设备本地处理。
- 未经用户明确操作，不上传照片、视频或面部数据。
- 明确区分“保存到 Mirage 作品”和“保存到系统照片”。
- 未来增加云端或 AI 功能时，必须在上传前单独说明。

## 12. 异常状态与降级策略

| 状态 | 产品表现 |
|---|---|
| 相机权限拒绝 | 展示说明卡片和“前往设置”按钮 |
| 不支持世界追踪 | 提示设备不支持空间模式，保留普通相机能力 |
| 不支持面部追踪 | 隐藏相关特效，或切换到普通前置相机滤镜 |
| 未检测到平面 | 持续显示轻量扫描提示，不显示错误弹窗 |
| 特效加载失败 | 自动回到原相机并展示 Toast |
| 内存不足 | 卸载未使用资源，降低粒子数量与贴图质量 |
| 设备过热 | 降低渲染帧率或关闭高成本效果并提示用户 |

## 13. 数据指标

MVP 阶段重点验证用户是否能理解和完成主流程，而不是追求复杂商业指标。

### 13.1 核心指标

- 首次授权相机成功率。
- 首次进入后完成一次特效选择的比例。
- 首次进入后完成一次拍摄的比例。
- 每次会话平均切换特效次数。
- 拍摄后触发保存或分享的比例。
- 特效加载成功率。
- 相机页面崩溃率和平均帧率。

### 13.2 关键漏斗

```text
启动 App
 → 相机授权
 → 进入相机
 → 选择特效
 → 特效成功呈现
 → 拍摄
 → 保存或分享
```

## 15. MVP 验收标准

### 15.1 功能验收

- 用户首次进入能正确申请相机权限。
- 授权后能看到实时相机画面。
- 用户能在自拍和空间模式间切换。
- 当前设备不支持自拍追踪时不会崩溃。
- 每个内置特效都能被选中、展示和移除。
- 切换特效不会残留上一个特效实体。
- 用户能拍摄包含特效的照片。
- 拍摄后能通过系统面板保存或分享。

### 15.2 体验验收

- 首次用户无需说明即可找到快门和镜头切换按钮。
- 选择特效后 3 秒内获得视觉反馈或明确引导。
- 主要按钮的可点击区域不小于 44 × 44pt。
- 明暗相机背景下，文字和按钮保持可辨识。
- 特效切换过程中界面保持响应。

### 15.3 性能目标

- 支持设备上相机预览目标为 60fps，复杂场景最低不低于 30fps。
- 普通特效首次加载目标不超过 2 秒。
- 连续切换特效不产生明显的内存持续增长。
- 进入后台时暂停 ARSession，恢复前台时正确重启。

## 16. 当前原型与下一步

当前工程已经具备相机主页、模式切换、示例特效、拍照分享、权限处理和 `MirageEffect` 扩展接口，可以作为 V0.1 的实现基础。

建议下一步按以下顺序推进：

1. 在支持 ARKit 和 TrueDepth 的真机上完成全流程验证。
2. 将光环示例升级为真正的环形网格和动画材质。
3. 增加点击放置、拖动、双指缩放和旋转。
4. 建立独立的特效包目录及 `manifest.json` 模型。
5. 接入视频录制和本地作品库，进入 V0.2。
